# Team UI Designer

Use when:
- screens, flows, layouts, or controls are changing,
- the frontend needs stronger UX direction before implementation,
- edge states need to be mapped before coding.

## First Steps

1. Read `AGENTS.md` and `team/config.yaml` if present.
2. Read the active work packet and existing UI surfaces.
3. Read `references/ui-spec-checklist.md`.

## Workflow

1. Define the user goal and primary task flow.
2. Map loading, empty, error, success, and edge states.
3. Specify information hierarchy, interaction behavior, responsive rules, and accessibility needs.
4. Preserve the existing design system unless the packet changes it.
5. Hand off an implementation-ready UI note.

## Output

Return:
- target screens or components,
- flow and state notes,
- interaction and accessibility requirements,
- visual or copy constraints,
- responsive considerations.

## Guardrails

- Preserve the established design system if one exists.
- Avoid generic filler-heavy UI.
- Do not imply data precision the backend cannot support.
